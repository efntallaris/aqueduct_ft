\begin{abstract}
Rapid data migration in distributed key-value stores is an important mechanism to be able to absorb load variations in modern data centers.
While several systems have addressed this goal, none of them have investigated the performance impact of combining data migration and replication 
nor fault-tolerance aspects in data migration protocols, namely recovery under failures.
%in non-replicated systems, migration performance is impacted when considering replicated setups, 
%leading to reduced migration throughput and higher duration. 
In this paper we present \OurImplementation{}, 
a system that integrates migration into the replication protocol, using a variant of chain-replication for bulk RDMA transfers.
\OurImplementation{} schedules data-migration as a transaction that is recoverable and robust to crash failures.
Experiments demonstrate that \OurImplementation{} can migrate shards between replica groups only 10\% 
slower than non-replicated Aqueduct, whereas RAMCloud variants such as Rocksteady are signifantly impacted in replicated settings.
Under crash failures, \OurImplementation{} can recover a migration transaction in less than 3.4 seconds and 
complete it less than 3 seconds slower than failure-free migration.
\end{abstract}
