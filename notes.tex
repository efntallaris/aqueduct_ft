\paragraph{Why a slot-aware allocation policy instead of a scattered layout?}
Where the benefit is real:
\begin{itemize}
  \item \emph{Zero copy on both ends.}
  With scattered pairs, the donor has to pack them into a buffer, which costs CPU time and a memory copy, or send many tiny scatter-gather entries.
  With the slot-aware allocator, the blocks already are the transfer unit.
  They also land on the recipient in their final place, so the recipient only rebuilds its index and never unpacks data.
  \item \emph{Far fewer RDMA operations.}
  A few large writes can reach full link speed.
  Many small key-value writes are limited by how many messages per second the network card can handle, so they don't.
  \item \emph{CPU left for clients.}
  Because neither side copies data, migration takes almost no CPU away from foreground requests.
  This is probably the strongest argument.
\end{itemize}
